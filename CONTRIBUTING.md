# Contributing Guidelines

Thank you for your interest in contributing to the Chaos Monkey QA Automation Testing repository!

## How to Contribute

### Reporting Issues
- Use the GitHub Issues feature to report bugs or suggest enhancements
- Provide clear descriptions with reproduction steps
- Include relevant test case information and documentation

### Submitting Changes

1. **Fork the repository** to your personal GitHub account
2. **Create a feature branch**: `git checkout -b feature/your-feature-name`
3. **Make your changes** following our standards:
   - Follow existing documentation formatting
   - Use clear, descriptive commit messages
   - Update relevant README sections
4. **Test your changes** thoroughly before submitting
5. **Submit a Pull Request** with:
   - Clear description of changes
   - Reference to related issues
   - Summary of test coverage

### Documentation Standards

- Use Markdown for all documentation files
- Include clear section headers and navigation
- Provide examples and code snippets where applicable
- Maintain consistent formatting with existing documents
- Add references to related Sprint or methodology documents

### Test Case Contributions

When adding new test cases:
- Follow the existing BVA (Boundary Value Analysis) format
- Include clear test case IDs
- Document expected results and actual results
- Map to specific requirements where applicable
- Add traceability information

### Commit Message Guidelines

Use clear, descriptive commit messages:
- `docs: Update README with new test case section`
- `feat: Add Sprint 3 Chapter 4 notes`
- `fix: Correct BVA test case boundaries`
- `refactor: Reorganize test case documentation`

## Code of Conduct

- Be respectful and professional in all interactions
- Provide constructive feedback on pull requests
- Help others learn and improve
- Report inappropriate behavior to the repository owner

## Questions?

If you have questions about contributing, please:
1. Check existing documentation in relevant Sprint folders
2. Create a GitHub Issue with your question
3. Contact the repository owner for clarification

Thank you for helping improve this QA documentation and testing resource!
